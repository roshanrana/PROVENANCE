# S-02, run #6 — a verdict that was wrong, and why it is kept

**Date:** 2026-09-07 · **Repo SHA:** `86dbc86` · **Where:** GitHub Actions,
`ubuntu-latest`, kind v0.33.0 · **Run:** BARRIER cluster #6, 4m 55s, green
**Verdict as printed: `ORACLE VIABLE`. That verdict is a false positive.**

This is the first time BARRIER's topology has stood up and the spike has run.
Both facts are worth recording. The verdict is not.

## What the run printed

```
probes: 24
  note: latency hit median=214.8ms miss median=214.5ms — NOT evidence either way
        on the simulator, which does not vary TTFT on cache hit vs miss (D-01).
        Recorded for completeness only.

client-observable discriminators: ['header:x-envoy-upstream-service-time']

VERDICT: ORACLE VIABLE — client-observable discriminator(s) found
```

## Why it is wrong

`x-envoy-upstream-service-time` is Envoy's own upstream latency for that
request, in milliseconds. Two requests essentially never take the same number of
milliseconds, so the header differs between **any** two probes regardless of
cache state. It classifies nothing.

The refutation is three lines above it in the same output. Hit median 214.8 ms
against miss median 214.5 ms — 0.3 ms apart — on a simulator that by
construction does not vary TTFT on cache hit versus miss (D-01, upstream issue
#347, closed as not-planned). The timing carried no cache signal, and the spike
counted a header derived from that timing as a signal anyway.

## The defect

`find_discriminators` implemented "fields that differ", while its own docstring
promised "fields that differ *for reasons related to routing*", and bridged the
gap with a five-entry ignore-list: `date`, `content-length`, `x-request-id`,
`server`, `connection`. An ignore-list only excludes the noise you already
thought of. `x-envoy-upstream-service-time` was not on it.

It is now a property test rather than a name list. A field counts only if it is

* **consistent** — differs in *every* hit/miss pair, not merely some; and
* **classifying** — its value is a property of the class, not of the request. A
  field taking a fresh value on every probe on both sides is measuring the
  request.

Fields that differ but fail either test are published in the evidence JSON under
`rejected_candidates`, with the reason. "We looked and rejected it" and "we never
looked" are different claims and only one of them is checkable.

**This is a defect fix, not a change to the decision rule.** LLD §7 fixes what
the *verdict* means and is untouched. It never said a differing field is a
signal.

## Why this run is kept

Because the project's claim is that its numbers can be checked, and the only way
to make that claim credible is to leave the checkable mistakes in. This is the
second time a result was published-shaped before it was right — see defect #6 in
the ship report, where a guard against a mislabelled comparison contained the
bug it was written to prevent, and produced an H100 result that was the exact
opposite of the truth.

The pattern in both: **the refuting evidence was already in the output.** A
32-trial cell finishing in zero seconds; a 0.3 ms median gap under a header
claimed as a discriminator. Nothing external was needed to catch either.

## What the run does establish

Independently of the verdict, run #6 is the first evidence that the topology
works end to end:

| | |
|---|---|
| EPP | 1/1 Running — `gRPC server listening name=ext-proc port=9002` |
| Gateway | 1/1 Running — `cm init: all clusters initialized` |
| Simulators | 2/2 Ready |
| Spike | 24 probes, gateway answered every one |

So F-18 (no `ext_proc` filter), F-20 (`ko` could not tag on a multi-node kind
cluster), F-21 (the EPP config named a plugin that does not exist) and F-22 (the
simulator's latency flags are Go durations) are all closed by a run rather than
by an argument.

## What happens next

Re-run under the corrected rule. **The verdict is not recorded in
`decisions.md` until then**, and no oracle code is written before it is — the
same discipline as S-03 and the pre-registered statistics. Both outcomes remain
publishable: `NO CLIENT-OBSERVABLE SIGNAL` rescopes FR-B-03 to an instrumented
demonstration, which NFR-17 was written to survive.
