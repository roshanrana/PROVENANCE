# PROVENANCE — Agent Instructions

Verifiable and tenant-isolated LLM inference for regulated environments. Two workstreams:
**ATTEST** (inference reproducibility as a model-risk control) and **BARRIER** (KV-cache
prefix locality as a cross-tenant leak, and its mitigation).

This project is **fully designed and approved**. Requirements, architecture, contracts, and a
50-task execution plan already exist. Your job is to execute the plan, not to redesign it.

> Loaded into every agent's context. Keep it short and rule-dense — background lives in
> `docs/design/`, read by pointer, on demand.

---

## Start here, every session

1. Read **`STATE.md`** — the single source of truth for where the project is.
2. Read the **task pack** you were given, in `docs/tasks/`.
3. Read **only the files that pack lists in its File scope.**

Never begin with a repo-wide crawl, a `git log` review, or "let me get familiar with the
codebase." `STATE.md` exists precisely so that is never necessary. If the pack points to a
spec section — "LLD §4.1" — read *that section*, not the whole document.

## Non-negotiables

- **Stay in scope.** A task may create or modify only the files its pack lists. If the task
  cannot be done without touching another file, **stop** — mark the task `blocked`, write
  what you found into the pack, and return. Blocked beats improvised.
- **Contracts in `docs/design/03-lld.md` §4 are frozen.** Field names, signatures, exit
  codes. If reality contradicts one, that is a plan change requiring human sign-off, not a
  judgment call. Never quietly adapt a contract so your code compiles.
- **`make check` must be green** before any task is marked done.
- **Two strikes.** Run the pack's Validation commands. Failing → fix and re-run *once*.
  Failing twice → stop, write findings and hypotheses into the pack, mark `blocked`. No
  third attempt. Thrashing loops are the largest waste in this system, and a second failure
  usually indicts the pack or the design rather than the code.
- **`common/` is a leaf** — it must never import from `attest/` or `barrier/`.
- **Never log** private keys, tenant API keys, the EPP salt secret, or derived salts. A
  derived salt in a log is a forgeable credential.
- **Fail fast.** This is measurement code. A silently degraded run produces a plausible
  wrong number — the worst available outcome for a project whose entire value is
  credibility. Never swallow an error to keep a run alive.
- **No drive-by refactors.** No renaming, no reformatting unrelated files, no adding
  dependencies the pack does not name.

## Evidence discipline

Every number appearing in the README or a writeup must trace to committed raw output plus
the exact command and git SHA that produced it. Figures are regenerated by script, never
hand-edited. `bench/results/<run-id>/` is immutable once written — a re-run creates a new
run-id, never an overwrite.

Negative results are published with the same rigour as positive ones. An experiment that
fails to show the expected effect is a finding, not an embarrassment.

## Definition of done, per task

1. Every Acceptance criterion in the pack is met — **including the negative and error
   cases**, which are criteria, not afterthoughts.
2. The pack's Validation commands pass.
3. Handoff notes filled in the pack: **≤10 lines**.
4. One line appended to the `STATE.md` task log.
5. Committed as `T-###: imperative summary`.

Tests must assert real behaviour. A test that cannot fail is worse than no test — it buys
false confidence at the reviewer's expense.

## Toolchain

Python 3.12 via **uv** — `uv run …`, never bare `python`. Go 1.24, confined to `barrier/epp`.
`make check` runs both toolchains and must complete in under five minutes.

## What is not yours to run

Nine tasks need hardware no agent can reach: **T-032, T-033, T-035, T-040, T-041, T-042,
T-043, T-044** need a local kind cluster, and **T-028** needs a rented NVIDIA GPU. Their
packs are written as self-contained scripts that record their own output into
`bench/results/`. Write the script; do not attempt to run the cluster or the GPU.
